Canvas, 23 widgets, every screen, the render loop. No ESP header
(`test/check_no_esp_headers.sh`).

A screen is a pure function of one Frame: `update()` sets widget values and
must not draw. `render` sends only what changed (`Widget::damage()`,
`ui::App::damage()`), through `ui::Shadow`, the copy of the glass in PSRAM.
Anything that moves must be a widget; background chrome is drawn only on a
full repaint.

`Canvas` is an interface; `FrameBufferCanvas` implements it over a plain
RGB565 buffer (a band in PSRAM on the device, an array in `test_ui`), so
"does the lap screen show the right time" is a unit test. `test_ui` draws
every screen against a fake Frame, including one with nothing published,
where every reading must come out `--`.

`ui::App` keeps one screen alive at a time. **A new screen** goes in
`ScreenId`, `ui::AllScreens` and `App::build()`; anything that must outlive
it (traces, lap history, CONFIG's place) the App holds and hands back.
`chrome.hpp` is the shared furniture (titles, rules, tiles); `theme.hpp` the
meaning of colours over `geometry.hpp`'s palette. Large text is
anti-aliased from `font_aa.cpp`, generated by `tools/gen_font.py`.

`docs/features.md` §4–§11 describes every screen and overlay.
